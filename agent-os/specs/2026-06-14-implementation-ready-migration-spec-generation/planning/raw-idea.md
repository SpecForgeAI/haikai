Spec 1 of a 4-spec migration auto-flow program — "Implementation-Ready Migration Spec Generation".

GOAL: Enrich the existing migration shape-spec generation so each Story in a saved migration book of work comes out as a genuinely IMPLEMENTATION-READY spec that does TWO things: (1) populates the FULL implement-workspace screen state so a user opening the work item sees the Implementation screen EXACTLY as if they'd manually completed the Product Manager + Test Engineer conversations today; and (2) assembles into a single combined spec text (the "view spec" body) which is what later gets sent to the external shape-spec endpoint. This REPLACES auto-answering PM/TE conversations — we steer the generation up front instead (no circular self-Q&A).

KEY WORK:
- REVERSE-ENGINEER by CODE-TRACING (NOT a live run; do not start the stack) exactly what a completed manual PM→TE session persists across all stores: the implement-workspace (PersistedWorkspaceState in frontend/src/api/implementWorkspaceApi.ts + AMS work_item_implement_workspace JSONB: plannerPayload=scope/AC/assumptions/featureUnderstanding/implementationPlan, questions PM+SD, executionArtifactsByIncrement, teamChatTranscript), the sibling implement-state store (Test Pack + ready flags), implement-conversation, and the migration_story_spec_generations row. - ENRICH the generator: gateway/src/services/migrationShapeSpecGenerationHandler.ts + prompt gateway/src/config/prompts/product-manager.migration-shape-spec-generation.task.md + the SpecGenerationResponse schema. Fold in the Product Manager scope-in/out + testable-acceptance-criteria discipline (harvest from gateway/src/config/prompts/product-manager.implement-support.task.md) and the Test Engineer structured unit/functional test pack mapped per acceptance criterion aligned to TEST-STRATEGY.MD (harvest from gateway/src/services/testPlanningPrompt.ts). Upgrade today's flat tests:string[] to a structured test pack.

- ASSEMBLE the combined spec text per story (the /agent-os:shape-spec body) = the "view spec" the user can open and that Spec 3 sends to the external shape-spec endpoint.
