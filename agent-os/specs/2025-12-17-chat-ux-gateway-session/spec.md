# Specification: Chat UX and Gateway Session Ownership

## Goal
Fix chat panel layout to occupy full viewport height with a pinned, user-resizable message entry area, and update Gateway to own sessionId creation for both chat endpoints.

## User Stories
- As a user, I want the chat panel to fill the available height so the input area stays pinned at the bottom and does not shift when messages are added
- As a frontend developer, I want the Gateway to generate sessionIds so the client can send chat requests without pre-generating session identifiers

## Specific Requirements

**Chat panel vertical flex layout**
- ChatPanel must use `display: flex; flex-direction: column; height: 100%; min-height: 0; align-self: stretch`
- Header region uses `flex: 0 0 auto` to maintain fixed height
- MessageBubbleArea uses `flex: 1 1 0; overflow-y: auto; min-height: 0` for independent scrolling
- MessageEntryArea uses `flex: 0 0 auto` with a height controlled by state
- All intermediate containers in the hierarchy must have `min-height: 0` to enable nested flex scroll

**Collapsed chat tab full height**
- Collapsed state renders as a narrow vertical tab occupying full available height (100vh - 60px TopBar)
- Thin grey vertical border visible from top to bottom of the collapsed tab
- Existing `collapsedTab` CSS already has correct structure; verify `height: 100%` and `align-self: stretch` are present

**Dedicated drag handle for input area resizing**
- Add a visible drag handle bar (8px height) between MessageBubbleArea and MessageEntryArea
- Cursor changes to `ns-resize` when hovering/dragging the handle
- Implement `inputHeight` state in ChatPanel, default value 100px
- On mousedown + mousemove, calculate new height and update state
- Textarea inside MessageEntryArea uses `height: 100%` to fill the resizable container

**MessageEntryArea scrolling behavior**
- Textarea has `overflow: auto` so content scrolls internally when exceeding container height
- Remove native `resize: vertical` from textarea CSS (custom drag handle replaces it)
- No min/max height constraints per user preference

**MessageBubbleArea scroll stability**
- Adding new messages must not push or jerk the MessageEntryArea
- `flex: 1 1 0` with `min-height: 0` ensures the bubble area absorbs all available space
- Existing auto-scroll logic in ChatMessageList should continue to scroll to bottom for new messages

**Gateway: make sessionId optional in POST /api/chat validation**
- Update `validateChatRequest()` in `validation.ts` to remove sessionId from required fields
- If sessionId is provided, validate it is a non-empty string after trim
- If sessionId is missing/blank, validation passes (handler generates it)

**Gateway: make sessionId optional in GET /api/chat/stream validation**
- Update `validateStreamRequestMiddleware()` to skip sessionId validation when not provided
- Remove call to `validateSessionId()` when query param is undefined or empty
- Same rules as POST: missing/blank sessionId is acceptable

**Gateway: generate sessionId in chat handlers when missing**
- In POST `/api/chat` handler, if `body.sessionId` is undefined/null/blank after trim, generate `sessionId = uuidv4()`
- In GET `/api/chat/stream` handler, if `query.sessionId` is undefined/null/blank after trim, generate `sessionId = uuidv4()`
- Call `getOrCreateSession(sessionId)` with the provided or generated sessionId
- Log `session_created: true` when a new sessionId is generated by the handler

**Gateway: response always includes sessionId**
- POST `/api/chat` response already returns `sessionId` in ChatResponse; ensure it uses the actual (possibly generated) value
- GET `/api/chat/stream` final SSE event should include `sessionId` field so frontend can store it for subsequent requests
