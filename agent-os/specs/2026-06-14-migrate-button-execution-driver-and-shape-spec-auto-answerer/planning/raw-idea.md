Spec 3 of a 4-spec migration auto-flow program — "Migrate Button + Migration Execution Driver + External Shape-Spec Auto-Answerer".

GOAL: A single "Migrate" button (over a human-reviewed book of work) kicks off the fully-automated implementation half. The Migration Execution Driver — GATEWAY-HOSTED control + AMS run-state, event-driven, plus a lightweight background-async runner — drives each implementation-ready spec (stories from Spec 1 + TEST items from Spec 2) through: the external Software-Developer shape-spec stream WITH an auto-answerer answering its questions → an orchestration job → advance on the build-results "implemented" callback / halt on "failed" → BIG-BANG: only the FINAL spec sets deploy_on_complete=true → on the "deployed" callback, mark the run deployed and hand off to reconciliation (Spec 4).

KEY WORK:
- "MIGRATE" BUTTON (frontend) over a reviewed book of work, with a ready-to-migrate predicate (every in-scope spec generated/non-stale/no missing inputs; insufficient_context stories surfaced) + a confirm gate. Scope of one Migrate = ONE BOOK OF WORK.
- MIGRATION EXECUTION DRIVER (gateway control + AMS run-state): build the ORDERED sequence of the plan's implementation-ready specs — stories, plus TEST items AFTER the stories they span (Spec 2). Submit ONE spec at a time: feed its combined spec text to the external shape-spec stream → on stream done (folder+session) → startOrchestrationJob → wait for the build-results callback → "implemented" advances to the next spec; "failed" HALTS the run and surfaces it; only the FINAL spec carries deploy_on_complete=true; the resulting "deployed" callback marks the run deployed → hand off to reconciliation (Spec 4). EVENT-DRIVEN over persisted run-state (each callback steps the run forward; no long-held in-memory loop; restart-safe). A LIGHTWEIGHT BACKGROUND-ASYNC RUNNER handles the autonomous per-spec shape-spec-auto-answer segment (minutes-long; not request-driven).
- EXTERNAL SHAPE-SPEC AUTO-ANSWERER: drive the SSE shape-spec stream (gateway POST /api/v2/shape-spec/stream → external Claude Code) — read each streamed question and answer it via a bounded LLM loop (REUSE the Architect chassis: gateway/src/services/architectConversation/openPhaseLoopRunner.ts + buildOpenPhaseGrounding) grounded by the implementation-ready spec (the combined spec text) + oracle context (the existing gateway context resolvers). It DECIDES (best grounded recommendation) and NEVER abstains/halts; it RECORDS each decision + rationale in the run transcript. On stream conclusion (folder + session_id, no more questions) → submit orchestration.
- BUILD-RESULTS RECEIVER + DISPATCH (the single inbound door): POST /api/implementation/build-results — parse outcome + job_id/bug_id, persist, and DISPATCH. Spec 3 owns the door + the JOB_ID paths (implemented→Driver advance; failed→Driver halt; deployed→mark deployed). Spec 4 EXTENDS the same door with the bug_id paths + the reconciliation trigger. Matches the external service's pinned contract (snake_case + camelCase-tolerant, outcome enum implemented|deployed|failed|rejected, per-request callback_url, target_base_url on deployed).
- RUN-STATE PERSISTENCE (AMS new Liquibase changeset, after Spec 1's): migration_execution_run + migration_execution_run_item (per-spec status/job_id/branch/pr_url, run progress, current position, halt state, the auto-answerer decision log ref).
- DRIVER RUN-PROGRESS VIEW (frontend): show the run advancing through specs (per-spec status, current, halted, deployed) + the auto-answer decision log.

LOCKED DECISIONS: BIG-BANG (deploy only on the final spec → one deploy + one reconciliation); Migrate scope = one book of work; auto-answerer DECIDES + LOGS, never abstains (user trusts Claude's judgement; reconciliation break→bug is the structural backstop); GATEWAY-HOSTED, not a separate microservice, plus a lightweight background runner; single-spec-per-orchestration-job (external contract enforces).

OWNERS: gateway (Driver control + auto-answerer + build-results receiver/dispatch + background runner); architecture-model-service/AMS (run-state tables; new Liquibase changesets ONLY — coordinate numbering after Spec 1's; snake_case wire; boxed PATCH-mutable types); frontend (Migrate button + confirm + run-progress view).

OUT OF SCOPE: the spec generation (Spec 1); TEST item creation (Spec 2); the reconciliation replay + bug-report send + scoped re-reconciliation + circuit breaker (Spec 4 — Spec 4 extends the build-results door with the bug_id/deployed-reconcile paths). The external service's deploy + build-results emission is already built on their side.

REUSE: startShapeSpecStream / frontend useShapeSpecStream + gateway routes/shapeSpec.ts (SSE proxy); startOrchestrationJob + gateway routes/orchestrations.ts v2/jobs; the Architect chassis (openPhaseLoopRunner + buildOpenPhaseGrounding) for the auto-answerer; gateway/src/services/contextResolvers.ts for grounding; gateway routes/implementationProjects.ts (the /api/implementation namespace) for the build-results door; the implement-state.json + spec rows from Specs 1-2.
