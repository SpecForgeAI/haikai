The Inputs

Input Questions — Asked Per Workstream, Not Per Project

A real program ("modernize the risk estate") is several workstreams with different answers. Score each stream separately; expect different postures side by side.

1

Oracle strength

Can a machine verify the output today — tests, baselines, build signals, a running reference system? If not, can one be built, at what cost?

Decides → the autonomy ceiling

2

Repetition & volume

How many similar units of work — one-off, hundreds, or an indefinite backlog?

Decides → whether factory / automation setup amortizes

3

Spec-ability of intent

Is what's wanted knowable upfront (a regulation, an existing system's behavior) — or must it emerge through iteration and user feedback?

Decides → spec-driven vs exploratory posture

4

Blast radius & reversibility

Production criticality, regulatory exposure, rollback cost, evidence requirements?

Decides → where the human gates go (not which approach)

5

Lifecycle scope & boundary

Which segment of the lifecycle is this? What artifact must cross into the next segment, at what quality bar?

Decides → the handoff contract (e.g. prototype dies, learning crosses)

6

Organizational readiness

Harness & tooling maturity, engineer fluency, and can governance accept machine-generated evidence?

Decides → the practical ceiling — often the binding constraint in a bank

Companion Approaches

Vibe Coding

Conversational prototyping — no spec, no gates. Legitimate when the artifact is disposable: its output is learning, not code.

Copilot / Inline Assist

Autocomplete & in-IDE suggestion. No delegation — where most engineers start, and the on-ramp to a harness.

Background Task Agents

Fire-and-forget bounded tasks — a ticket, a review, a refactor — returning a PR. A loop per ticket, without a pipeline.

Ambient / Policy Agents

Standing agents watching a repo or estate — triage, drift alerts, proposals. Continuous work, not project-shaped.

Judge Panels & Critics

Generator–critic–judge ensembles and adversarial verification. A quality technique, not an approach — slots inside any approach.

Deterministic Processing

Plain non-AI code — scripts, rules, parsers, checks. When the logic is knowable, write it once and trust it every time — slots inside any workflow.

The Lifecycle

Map the Lifecycle, Contract the Boundaries

Techniques are chosen per segment. Artifacts are contracts between segments. Humans guard the boundaries — that's where intent gets translated, and translation is where irreversible errors happen.

Discover

Harness / conversational

No oracle exists; novelty is total. Human drives, AI explores & drafts.

Human: decision-maker

Prototype

Vibe coding — scoped as disposable

An instrument for generating validated requirements. Output is learning, not code.

Human: user-feedback collector

Specify / Design

Spec-Driven

Intent crystallizes into reviewable artifacts; disagreement resolves in favor of the spec.

Human: spec author & reviewer

Build

Factory (at volume) / SDD unit

Agents implement from verified specs; pipeline dispatches & tracks.

Human: exception handler

Verify

Loop vs oracles

Iterate to green against tests, baselines, parity checks. Evidence recorded.

Human: none inside the loop

Release & Operate

Ambient agents + loops

Gated release on evidence; standing agents watch, triage, propose.

Human: outcome & evidence reviewer

Worked Examples

The Output Is a Delivery Design

Example A

Regulatory Reporting Platform

Complex UI over a complex estate; periodic submissions to the regulator.

1
Oracle — mixed: calcs testable, UI needs human eyes
2
Repetition — low-mod: shared patterns, bespoke reports
3
Spec-ability — high: the regulation is the spec
4
Blast radius — severe: misreporting = breach
5
Scope — full PDLC: discovery → operate
6
Readiness — sign-off culture, reviewable evidence
Possible Setup
Discover
Harness explore the estate & the regulation
Prototype
Vibe disposable UI prototypes with end users
Build
Spec-Driven phase-gated (possibly Factory across reports) · Deterministic calc core
Verify
Judges critique report outputs + human review
Human gate
every submission human-approved
Example B

Legacy Settlement Engine Migration

Sybase + Java 8 → modern stack; ~200 endpoints, ~80 tables; behavior fully defined by the running system.

1

2
Repetition — high: hundreds of same-shape units
3
Spec-ability — high: legacy defines the behavior
4
Blast radius — high: parity + staged cutover de-risk
5
Scope — build-verify heavy: capture → reconcile
6
Readiness — needs capture investment first
