## [2026-06-01] decision | inbound-gateway contract + always-fresh re-entry
Walked the inbound-gateway contract. **What comes inbound** (all → a verdict for one cell): CI runs (`ci-trigger`), quality/security (`observe`), poll fallback, the internal TTL sweeper (`timeout`), and a reserved non-verdict branch. **After receipt**: authenticate (ingress-token→secret, signature), dedup (delivery id), correlate (SHA→cell via the D10.4 binding), map status, `record_verdict` (guarded), then hand off. **Decision (amends D10.2):** re-entry is **always a fresh invocation, never a resumed session** — context is always provided by reading the db (spec slice + detail + verdicts); D10.6 single-flight is a per-orchestration queue. **The fork is uniform**: pass/pending resolve in the loop from verdict rows alone; only `fail` loads full context (log + diff + spec + rubric), and that's the `repair-engine` subagent, scoped to the one cell — the loop stays cheap. The whole decision framework is Agent-OS **prompts, no code**; the only code is the gateway + guarded recorder tools + db + SSE. Swept all "resume-or-fresh" wording to "always fresh"; diagrams re-pushed.
