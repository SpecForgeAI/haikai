# Structural store

The on-disk artifact produced by the AST pipeline. Flat text files designed to be **cheap for an LLM to grep**.

## What's in it

| File | Source | Contents |
|---|---|---|
| `_index.txt` | ctags | Symbols (functions, classes, methods) with file:line + signature |
| `_calls.txt` | tree-sitter | Call edges: `caller@file:line → callee` |
| `_imports.txt` | tree-sitter | Import relationships per file |
| `_inheritance.txt` | ctags | Class hierarchy (`Class → ParentClass`) |
| `_patterns.txt` | derived | Detected design patterns |
| `_stats.txt` | derived | Summary statistics |
| `<file>.struct` | per-file | Per-file detail used for inspection |

Code that writes them: `src/ast/store.py` (`FileStore`).

## Where they live

```
ast-reports/<job>/structural/<repo>/<commit-sha>/
  _index.txt
  _calls.txt
  _imports.txt
  _inheritance.txt
  _patterns.txt
  _stats.txt
  <file>.struct (many)
  diagrams/        ← generated by diagram builders
```

The `<commit-sha>` segment pins the snapshot to a real git SHA — see [[depgraph-commit-sha]].

## Why flat text

Two reasons:

1. **LLM-grep ergonomics.** A skill prompt can say "look at `_index.txt`" and the LLM grabs it via Read/Grep tools. No DB connector, no schema. This is the [[../decisions/structural-first-in-discovery]] principle.
2. **Human-readable diffing.** Two snapshots of the same repo at different commits diff cleanly with `diff`. This is the foundation for `src/ast/structural_diff.py`.

## Who consumes it

- **Agentic discovery skills** — the primary consumer. Endpoint/interaction discoverers read `_index.txt`, `_calls.txt`, `_imports.txt` to form hypotheses. See [[agentic-discovery]].
- **Diagram builders** — see [[diagram-generation]]; produces 8 diagram types in 4 output formats from the index files.
- **LLM formatter** — `src/ast/formatter.py` reads structural data and produces compact text for LLM prompts (replaces raw source).
- **V2 pipeline** — see [[v2-extraction-pipeline]]; V2 reads queries lazily from structural store on demand.

## Two providers feed it

The store is the merged output of two extractors:

- **CtagsProvider** — symbols, signatures, inheritance. Fast, 100+ languages.
- **TreeSitterProvider** — calls, imports, assignments, annotations. AST-precise, 8 languages.

See [[two-tier-code-intelligence]] for why both.
